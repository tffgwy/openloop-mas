# 统一资源索引与多格式预览

从 v0.7.71 起，这个项目有了一个**文件夹级别的答案**：
**这个循环到底产出了什么？**

以前这个答案是散的：`mas artifacts` 只列**交付物**，`mas status` 只讲**机器**，
一个既不是交付物、也没有任何验收标准提到的文件 —— 一份佐证 PDF、一个字体、
一个 3D 模型 —— **根本没有地方列**。

现在有两个命令：

```bash
mas files                  # 索引这台机器上所有工作区
mas files ./my-folder      # 索引一个文件夹
mas preview ./my-folder/out/report.pdf   # 预览一个文件
```

两个命令都有 `--json`，给脚本和 agent 用。

---

## `mas files`：一个文件夹就是一份索引

```bash
$ mas files ./out

共 1 个工作区，5 个文件：

[./out]  5 个文件  263.7 KB
    pdf        1 个
    image      2 个
    model      1 个
    zip        1 个
      836.0 B  pdf        report.pdf  pages 2、text chars 57
      327.0 B  image      shot.png  width 12、height 7
      117.0 B  image      liar.txt  width 4、height 4
      213.0 B  model      ascii.stl  triangles 2
      251.0 B  zip        bundle.zip  members 2
```

它保证三件事：

1. **每个文件都进索引，包括没人检查的辅助文件。**
   一个辅助文件也是这次工作的一部分 —— 没有验收标准提到它，
   不等于它不该被看见。

2. **格式按文件自己的头判定，不看名字。**
   上面的 `liar.txt` 其实是一张 PNG，所以它报 `image` 而不是 `text`。
   扩展名会撒谎，文件头不会。

3. **读不开的文件要列出来，并写明原因。**
   索引里那一行 ⚠ 是**信息**，不是噪声：交付物中间有一个读不开的文件，
   恰恰是读者最该看见的东西。**它不会被悄悄丢掉。**

### 事实从文件里读出来

索引不是只列文件名。它读文件自己的头，把能证明的事实读出来：

| 格式 | 读出来的实 |
| --- | --- |
| PDF | 页数、正文字符数 |
| PNG / JPEG / WEBP / TIFF / GIF / BMP | 像素宽高 |
| TTF / OTF / TTC / WOFF / WOFF2 | 字体家族、字形数、表数 |
| WAV | 时长、声道、采样率 |
| MP4 / MOV | 时长、轨道数、品牌 |
| FLAC / OGG / MP3 | 容器类型 |
| GLB / glTF | 网格数、节点数、材质数、动画数 |
| OBJ / STL / PLY / FBX / 3MF | 顶点数、面数、三角面数 |
| ZIP / Office 文档 | 成员数、正文字符数 |

**只报文件头能证明的事实。** 读不出来的字段就不报 —— 一个猜测
和一条事实，在读的人眼里长得一模一样。

## `mas preview`：读一个文件

```bash
$ mas preview ./out/report.pdf

report.pdf  pdf  836.0 B
  pages 2、text chars 57

Chapter One: the loop closes
Chapter Two: the index grows
```

* PDF 的字从**压缩流**里取出来，Word 的字从 **zip 成员**里剥掉标记取出来；
* 图片没有正文 —— 预览会**明确说「这个格式没有可预览的正文」**，
  而不是给你一个空白屏幕；
* `--max-chars N` 可以只取开头一部分；
* 文件不存在 → **退出码 2**，JSON 里是 `{"error": "file_not_found"}`；
* 传了一个文件夹 → **退出码 2**，并告诉你用 `mas files` 看它。

## 和 MOKI 的关系

MOKI 给 DeepSeek Harness 加了一个**本地资源管理器**：让 AI 生成的文件不再
散落各处，能在同一个工作区里统一管理；支持多格式预览；选中一段文字
按 `Alt+D` 唤起 AI 协同编辑，**修改先进草稿，用户审核确认后才写回原文件**。

OpenLoop MAS 走的是同一件事的**另一半**，而且是**闭环的那一半**：

| | MOKI | OpenLoop MAS |
| --- | --- | --- |
| 文件集中管理 | 插件内的资源管理器 | `mas files` 索引整个工作区 |
| 多格式预览 | 插件内预览器 | `mas preview`（纯标准库，不执行任何东西） |
| AI 协同编辑 | 选中文本 → `Alt+D` → **草稿 → 人工确认 → 写回** | 引擎侧的 overlay 语义**已经就位**（见 `mas engine` 的 `planned overlay`） |
| 谁来验收 | 人看 | **机器机检**（`content_*` 规则） |

**交互层还没有做。** v0.7.71 补的是**读的那一半**：
先把「有哪些文件、是什么、能读出么」这件事变成一条命令，
再谈「选中一段文字、唤起 AI、先进草稿、人工确认才写回」。

草稿确认那条路线的引擎侧语义**已经就位**：
worker 提出的改动先落进 overlay（草稿层），
**只有通过验收的改动才会写回磁盘**（写回层）。
「人在原工作区里改文件，交回后照样验收」这条回路已经有门禁守着
（第 11 项 `folder_handoff`）。

## 第 14 项门禁 `resource_index`

这一版的门禁盯着**资源索引这条路**：

* 文件夹里的每个文件都进索引，包括没人检查的辅助文件；
* 格式按文件自己的头判定；
* PDF 页数、字体家族、音频时长、模型三角面、压缩包成员都从文件里读出来；
* 预览能抽出 PDF / Word 的正文；
* 读不开的文件要列出来并写明原因，不能悄悄丢掉。

而且门禁**自己会失败**：它会**故意打断索引路径一次**，
确认自己注意到了 —— 一个不会红的门禁不叫门禁。

```bash
mas selftest --only resource_index
```

## 边界

* **只读。** 索引和预览**从不执行**文件里的任何东西，
  压缩包只是被**读**，不是被运行。
* **纯标准库。** 没有 Pillow、没有 mutagen、没有 trimesh。
  所以它在任何装了 Python 的机器上都能跑 —— 包括初学者的第一台机器。
* **事实只来自文件头。** 文件头没说的事，这里不报。
