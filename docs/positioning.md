# 定位说明 · OpenLoop MAS 与「私有化代理团队」类项目

> 这份文档写给要介绍、评测或二次开发 OpenLoop MAS 的人，
> 目的是把「我们做什么」和「我们不做什么」说清楚，避免宣传口径跑偏。

---

## 1. 一句话定位

**OpenLoop MAS 是多智能体系统的「闭环层」**：它不负责让智能体聊得更热闹，
它负责让「做完没有」变成一个**可被机器判定、可被复盘、可被止损、可被交接**的事实。

---

## 2. 两层架构

```
┌──────────────────────────────────────────────┐
│  执行层（谁来做）                              │
│  Claude / GPT / Kimi / 本地模型                 │
│  + MCP 工具 + 应用生态                          │
│  → 私有化代理团队类项目（OpenMausBot 等）       │
└──────────────────────────────────────────────┘
                    ↓ 产物
┌──────────────────────────────────────────────┐
│  闭环层（做完了没有）                           │
│  OpenLoop MAS                                 │
│  验收标准 → 机检判定 → 退出条件 → 账本 → 工单   │
└──────────────────────────────────────────────┘
```

两层可以叠加：前者当执行层，后者当闭环层。

---

## 3. 与 OpenMausBot 这类项目的关系

`OpenMausBot` 是 GitHub 上的开源项目，主打**私有化 AI 代理团队**：可以自行接入 Claude、GPT、Kimi 等模型，本地或云端运行，支持 MCP 协议并与大量应用打通。它常被介绍为「Grok Bot 的免费平替」。

| 维度 | OpenMausBot（执行层） | OpenLoop MAS（闭环层） |
| --- | --- | --- |
| 核心问题 | 让多个代理协同干活 | 让协同**真的会结束** |
| 判定 | 依赖模型自述 | 引擎机检优先，模型不能覆盖 |
| 退出条件 | 依赖对话自然收敛 | 迭代 / 墙钟 / token / 停滞 四道止损 |
| 过程记录 | 聊天记录为主 | append-only 闭环账本 |
| 人工介入 | 人工重开对话 | 工单 + `resume` 断点续跑 |
| 部署 | 需要 Docker / 模型服务 | 纯标准库，一条命令安装 |

### 3.1 传播口径

- 可以这样讲：**「让多智能体真的会结束的那一层」**，而不是「又一个聊天壳」。
- 可以类比：**执行层是发动机，OpenLoop MAS 是仪表盘 + 刹车 + 行车记录仪。**
- 不要把 OpenLoop MAS 说成 OpenMausBot 的复刻或替代品——两者是互补关系。

### 3.2 关于同类项目的引用纪律

引用 OpenMausBot 等第三方项目时：

- 能力边界、安全模型、更新频率**一律以其官方仓库说明为准**；
- 不要替别人的项目做安全承诺（不替第三方担保数据安全、不替第三方承诺生产可用性）；
- 本项目自身的定位描述只覆盖本项目自身的功能，**不评价第三方**；
- 「Grok Bot 的免费平替」是**该项目的第三方描述口径**，引用时保持归属清晰，不要写成 OpenLoop MAS 的定位。

## 4. 我们明确不做什么

| 不做 | 原因 |
| --- | --- |
| 不做 UI / 聊天前端 | 闭环层应该能被任何客户端调用，包括 CLI、MCP、CI |
| 不做模型路由与编排市场 | 编排策略是执行层的事，混在一起会两头不讨好 |
| 不托管用户密钥到远端 | 密钥只走环境变量或本地配置 |
| 不承诺「自动解决所有任务」 | 判定不了就升级人工，这是设计而不是失败 |

---

## 5. 差异化的硬指标（可以实测）

| 指标 | 怎么测 | 期望 |
| --- | --- | --- |
| 判定可复现 | 同一产物跑两次 | 判定逐条一致 |
| 模型不能自证通过 | 让模型输出「全部通过」但产物缺关键字段 | 引擎机检判不通过 |
| 无判定不放行 | 去掉 `check` 且模型不给 verdict | `unjudged`，按不通过 |
| 卡死能止损 | 连续产出完全相同的产物 | 连续 N 轮后升级人工工单 |
| 预算能止损 | 把 `max_iterations` 设成 1 | `budget_exhausted` |
| 过程可回放 | 读 `~/.mas/ledgers/runs.jsonl` | 每轮一条 append-only 记录 |
| 零第三方依赖 | `pip list` 对比 | 没装任何新包 |

这些都可以在 `python -m mas demo` 与 `python -m unittest discover -s tests` 里直接看到。

## 6. 目标用户

| 用户 | 痛点 | 怎么用 |
| --- | --- | --- |
| 初学者 | 不知道怎么把多智能体跑起来 | `install.ps1` / `install.sh` 一条命令，再 `mas demo` |
| 做内容的创作者 | 多轮改稿没有退出条件 | 写验收标准 + 机检规则，跑闭环 |
| 团队负责人 | 过程不可见、无法交接 | 账本 + 工单 + `resume` |
| CI 场景 | 想要一个可当门禁的判定器 | `mas run` 退出码 0/2 |

---

## 7. 一句话电梯稿

> OpenLoop MAS 是一个零依赖的多智能体闭环运行时：把「规划 → 执行 → 验证 → 复盘」
> 写成有验收标准、有退出条件、有过程账本的工程循环。
> 判定权在引擎不在模型，任务要么闭合、要么升级人工、要么预算止损——没有「差不多完成」。
